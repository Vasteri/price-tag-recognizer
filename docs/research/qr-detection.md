# Детекция QR: исследование готовых моделей и датасетов для дообучения

Дата исследования: 2026-09-22. Изучены первичные источники: репозитории авторов, опубликованные файлы весов, документация и исходники OpenCV. Модели не запускались; приведённые размеры — размеры файлов на GitHub, а не RAM, VRAM или замеры скорости.

## Рекомендация

Начать с готовых **QRDet nano и small** на собственных фотографиях. Это непосредственно обученные QR-детекторы. Проверить, хватает ли nano по recall, а small использовать для сравнения качества. Дообучение имеет смысл после разбора пропусков на реальных ценниках. Это инженерная рекомендация, не результат проведённого benchmark.

## Готовые кандидаты

| Кандидат | Веса | Выход и роль |
| --- | --- | --- |
| QRDet nano | `qrdet-n.pt`, 6.59 MB | YOLOv8 segmentation: bbox, confidence, polygon и четырёхугольник |
| QRDet small | `qrdet-s.pt`, 22.9 MB | Тот же API; размер по умолчанию в библиотеке |
| QRDet medium / large | 52.3 / 88 MB | Имеются готовые веса, но для начального сравнения лёгких моделей достаточно n/s |
| scardonac/qr_code_detection | `best.pt`, 5.96 MB | Отдельный пример YOLOv8n, дообученного на QR; bbox |
| OpenCV WeChat QRCode | detector 943 KB; SR 23.4 KB | Компактный CNN/SSD и super-resolution, готовый общий pipeline чтения |

Размеры QRDet подтверждены [списком assets релиза v2.0_release](https://github.com/Eric-Canas/qrdet/releases/expanded_assets/v2.0_release); nano и small можно получить напрямую: [qrdet-n.pt](https://github.com/Eric-Canas/qrdet/releases/download/v2.0_release/qrdet-n.pt), [qrdet-s.pt](https://github.com/Eric-Canas/qrdet/releases/download/v2.0_release/qrdet-s.pt). API и тип модели описаны в [QRDet](https://github.com/Eric-Canas/qrdet).

Альтернативный YOLOv8n подтверждён [репозиторием автора](https://github.com/scardonac/qr_code_detection) и [файлом best.pt](https://github.com/scardonac/qr_code_detection/blob/main/models/best_model/best.pt). Автор указывает Roboflow-датасет из 1547 изображений, обучение 30 эпох при 640 px и результаты на своей выборке. Эти цифры не дают основания сравнивать его с QRDet без общего теста. В просмотренном корне репозитория отсутствует отдельный LICENSE; условия для весов необходимо выяснить прежде, чем выбирать их для распространения. Поэтому это дополнительный исследовательский кандидат, а QRDet — основной.

Размеры WeChat: [detect.caffemodel](https://github.com/WeChatCV/opencv_3rdparty/blob/wechat_qrcode/detect.caffemodel), [sr.caffemodel](https://github.com/WeChatCV/opencv_3rdparty/blob/wechat_qrcode/sr.caffemodel). Для загрузки также нужны соответствующие `detect.prototxt` и `sr.prototxt` из [того же репозитория](https://github.com/WeChatCV/opencv_3rdparty/tree/wechat_qrcode).

## Особенности QRDet

- `QRDetector(model_size='n')` выбирает nano; значение по умолчанию — `'s'`. Начальные пороги: `conf_th=0.5`, `nms_iou=0.3`.
- `bbox_xyxy` подходит для первого crop, `quad_xy` и `padded_quad_xy` — для последующего выравнивания перспективы. Четырёхугольник аппроксимируется по сегментации, это не отдельная сеть определения четырёх углов.
- Детекция доступна отдельно от декодирования. Можно сохранить и передать на дальнейшую обработку QR, который пока не читается.
- Обёртка автоматически скачивает веса; в эксперименте стоит явно фиксировать их файл и версии зависимостей.

Источники: [описание API QRDet](https://github.com/Eric-Canas/qrdet), [код загрузки и вызова YOLO](https://github.com/Eric-Canas/qrdet/blob/main/qrdet/qrdet.py).

В просмотренном `qrdet.py` используется `YOLO(..., task='segment')`, `half=False`, `device=None`, `max_det=100`. Произвольные `kwargs` метода `detect` не передаются дальше в `model.predict`, поэтому `detect(imgsz=1280)` не следует считать рабочим способом изменить разрешение: для такого эксперимента надо управлять нижележащим inference или изменить адаптер. В верхнем комментарии файла осталось упоминание YOLOv7-tiny, но актуальный исполняемый код загружает YOLOv8 segmentation. [Источник](https://github.com/Eric-Canas/qrdet/blob/main/qrdet/qrdet.py).

У QRDet опубликован MIT LICENSE, однако автор отдельно указывает зависимость от AGPL-3.0 Ultralytics. MIT-маркировка обёртки не означает, что весь стек имеет только MIT-условия. Ultralytics описывает AGPL-3.0 и Enterprise варианты. Это сведения из источников, без вывода об условиях конкретного внедрения. [QRDet, Licensing clarifications](https://github.com/Eric-Canas/qrdet#licensing-clarifications), [Ultralytics](https://docs.ultralytics.com/models/yolov8/).

## Насколько они лёгкие

Размер готового QRDet nano — около 6.6 MB, но размер Python/PyTorch runtime и потребление памяти будут существенно другой метрикой. Их следует измерять отдельно. Для масштаба архитектуры Ultralytics публикует 3.4 млн параметров и 12.0 GFLOPs для стандартного YOLOv8n-seg при 640 px; для s-seg — 11.8 млн и 40.1 GFLOPs. Это характеристики стандартных COCO-моделей, не проверенные здесь точные параметры QRDet. [Таблица сегментационных моделей в исходнике документации](https://github.com/ultralytics/ultralytics/blob/main/docs/en/models/yolov8.md).

Обычный `yolov8n.pt` из Ultralytics обучен на COCO и сам по себе не является готовой моделью QR. Его можно рассматривать как инициализацию для обучения собственного QR-детектора; QRDet уже содержит специализированные веса. [Документация YOLOv8](https://docs.ultralytics.com/models/yolov8/), [QRDet](https://github.com/Eric-Canas/qrdet).

## Где полезен WeChat QRCode

OpenCV документирует две CNN: поиск bbox и увеличение небольшого QR. Публичный API объединяет поиск и чтение в `detectAndDecode`. [Документация](https://docs.opencv.org/4.x/d5/d04/classcv_1_1wechat__qrcode_1_1WeChatQRCode.html).

Существенное ограничение для задачи «найти нечитаемый QR и восстановить»: возвращаемые `points` в текущем исходнике относятся к успешно декодированным QR. Внутренние кандидаты детектора наружу этим API не выдаются. Поэтому готовый WeChat API хорош как baseline чтения, но для независимой детекции всех bbox понадобится обращаться к сети отдельно или делать адаптер. Веса надо передать явно: конструктор без путей отключает нейросетевой детектор и нейросетевой SR. [Исходник OpenCV](https://github.com/opencv/opencv_contrib/blob/4.x/modules/wechat_qrcode/src/wechat_qrcode.cpp).

В репозитории моделей указан Apache-2.0 с исключениями для перечисленных сторонних компонентов. [LICENSE WeChat](https://github.com/WeChatCV/opencv_3rdparty/blob/wechat_qrcode/LICENSE).

## Исследовательская альтернатива: BarBeR

В BarBeR авторы сравнили дообученные YOLOv8 Nano/Medium, Faster R-CNN, RetinaNet и RT-DETR на общем наборе штрихкодов. Репозиторий предоставляет обучение, протоколы сравнения и ссылки на готовые веса; портал загрузки требует учётную запись. Это полезнее для воспроизводимого сравнения, чем сопоставление mAP из разных любительских проектов. Однако стандартное сравнение использует группы 1D/2D: детекция 2D не равнозначна классификации именно QR. Архивы весов здесь не скачивались; их размеры и состав не проверены. [Репозиторий](https://github.com/Henvezz95/BarBeR), [статья ICPR 2024](https://federicobolelli.it/pub_files/2024icpr_barber.pdf).

Также в репозитории имеется BaFaLo — специализированная архитектура сегментации штрихкодов. Это дополнительное направление исследования; в рамках этой заметки её веса и преимущество именно на QR не установлены. [Раздел BaFaLo](https://github.com/Henvezz95/BarBeR/tree/main/BaFaLo).

## Датасеты для дообучения

Проверены страницы авторов и описание разметки. Архивы не скачивались, поэтому полнота файлов, дубликаты и фактическая доступность каждого файла внутри архивов не подтверждены.

### BarBeR: самый содержательный реальный источник

Полигоны можно преобразовать в bbox, сохранив исходные четыре вершины для задач геометрии. PPE и payload полезны для будущей оценки чтения, но доступны не для всех объектов: статья описывает 1 722 нечитаемых кода, размеченных вручную, без части таких полей. В сборник входят Dubská QR, Szentandrási QR, Bodnár-Huawei и ZVZ-real; нельзя добавлять эти же исходники в другую часть train/test без проверки пересечений. [Статья, раздел Dataset](https://federicobolelli.it/pub_files/2024icpr_barber.pdf).

У репозитория BarBeR указана AGPL-3.0. На открытой странице датасета отдельная лицензия данных не найдена; переносить лицензию кода на исходные фотографии нельзя. Условия архива остаются пунктом проверки. [Код](https://github.com/Henvezz95/BarBeR), [портал данных](https://ditto.ing.unimore.it/barber/).

### Roboflow: быстрый старт, но нужна чистка

На карточке проекта указана CC BY 4.0 и три названия класса: `qr_code`, `QR_CODE`, `qrcode`. Для одноклассовой задачи их следует свести к `qr`. Версия v3 содержит preprocessing `Stretch to 640x640`, без аугментаций; такое растяжение меняет пропорции исходных снимков. Для исследования маленьких QR желательно получить исходное разрешение. Опубликованные 97.8% mAP@50 относятся к модели и split этого проекта, а не к проверке на наших ценниках. [Карточка](https://universe.roboflow.com/krkkale-niversitesi-pnmrg/qr-code-ee1km), [версия v3](https://universe.roboflow.com/krkkale-niversitesi-pnmrg/qr-code-ee1km/dataset/3).

### BoofCV, ABBYY и SBD

BoofCV публикует изображения и benchmark, но результаты сравнения библиотек на странице относятся к 2019 году: использовать их как актуальный рейтинг нельзя. Ценность здесь — категории сложных случаев и разметка углов. Отдельная лицензия архива на просмотренной странице не установлена. [Источник](https://boofcv.org/index.php?title=Performance:QrCode).

ABBYY публикует обновлённые ссылки и зеркало ZVZ, а также подготовку разметки и сегментационные модели. Код имеет Apache-2.0; условия самих архивов требуют отдельной проверки. Для начального исследования удобнее унифицированная версия реальных данных в BarBeR. [Источник](https://github.com/abbyy/barcode_detection_benchmark).

SBD LR занимает по README около 2.2 GB, UHR — около 150 GB. Репозиторий генератора имеет MIT; отдельные условия архивов на просмотренной странице не установлены. Это источник синтетики и подхода к генерации, но не подтверждённый датасет магазинных ценников. [Источник](https://github.com/viplabB/SBD).

### Что не стоит путать с датасетом детекции целого QR

- [QR-DN1.0](https://data.mendeley.com/datasets/t2bdr663ms/2): 6 750 искажённых/зашумлённых QR с чистыми эталонами, CC BY 4.0. Получены после извлечения QR из watermarking, а не как обычные фото QR на ценниках. Полезен для отдельной темы восстановления; готовая разметка положения QR в естественной сцене не заявлена. В описании есть несогласованность чисел train/test; её надо разрешить по архиву перед использованием.
- [Finder Patterns (QR code)](https://www.kaggle.com/datasets/samygrisard/finder-patterns-qr-code): карточку полноценно прочитать не удалось. Нельзя по названию считать, что размечен весь QR, а не его поисковые маркеры. [YOLO-конверсия kolabit](https://github.com/kolabit/qr-codes) существует, но семантика исходной разметки и её лицензия здесь не подтверждены.
- Исходный обучающий набор QRDet не следует считать автоматически доступным вместе с весами: в просмотренных материалах подтверждены веса и API, но не отдельный воспроизводимый релиз обучающих изображений и аннотаций. [QRDet](https://github.com/Eric-Canas/qrdet).

## Вывод по моделям и данным

Мой исследовательский приоритет: **QRDet n/s как готовые QR-модели; BarBeR с фильтрацией QR как реальная база; Roboflow как дополнительный bbox-набор; SBD как синтетическое дополнение; BoofCV как независимая проверка сложных случаев**. Ни один из просмотренных источников не доказывает качество на конкретных магазинных ценниках.

Для будущего дообучения целесообразно сохранять четырёхугольники, если они уже есть: bbox можно получить из них, обратное восстановление перспективных углов из bbox неоднозначно. Если задача ограничена выделением crop, bbox-only модель тоже обоснована. Это выбор задачи, а не требование использовать сегментацию.

Собственная небольшая тестовая выборка ценников нужна для проверки переноса качества. Предлагаемые срезы: размер QR в пикселях после resize, смаз, наклон, блики, несколько кодов, отсутствие QR, Data Matrix и штрихкоды рядом. Последние особенно полезны как отрицательные примеры для QR-only модели. Это рекомендации к будущему эксперименту, не проведённое обучение.

## Эксперимент до решения о дообучении

Ниже — предлагаемый протокол, а не опубликованные результаты моделей.

1. Подготовить отдельную контрольную выборку реальных ценников: крупные/мелкие QR, перспектива, смаз, блики, несколько QR, изображения без QR и похожие структуры. Не разносить соседние кадры одной сцены между train и test.
2. Сравнить QRDet n/s при одинаковой обработке. Для собственных YOLO-кандидатов добавить вариант bbox-only. Измерять recall по размеру QR, ложные срабатывания на изображение, точность границ и latency p50/p95 на целевом CPU/GPU; отдельно cold start и память.
3. Проверить влияние разрешения детектора. Crop для последующего чтения брать из исходного изображения. Пример геометрии: QR шириной 60 px в фото шириной 4000 px при уменьшении до 640 px занимает около 9.6 px — здесь одного увеличения размера модели может быть недостаточно. При пропусках маленьких кодов сравнить обработку тайлами.
4. Сохранять причины неуспеха раздельно: QR не найден; найден, но crop обрезан; crop корректен, но данные не читаются. В перспективе основная end-to-end метрика — точное совпадение payload с эталоном, а не только mAP детектора.
5. Дообучать на обнаруженных типах пропусков и негативных примерах, затем проверять на неизменном отложенном наборе. Для bbox-only модели нужны bbox; для продолжения segmentation-подхода нужны корректные маски/полигоны.

## Последующее чтение и восстановление

Идея «детекция → crop → попытка чтения → дополнительные преобразования только после неудачи» согласуется с существующими решениями. QReader уже объединяет QRDet, Pyzbar и предобработку. [QReader](https://github.com/Eric-Canas/QReader).

Инженерная рекомендация для будущего этапа: сначала сравнить исходный crop, геометрическое выравнивание, несколько масштабов и вариантов бинаризации. Нейросетевое восстановление оценивать по правильности считанного payload на известных примерах: улучшение внешнего вида QR само по себе не доказывает восстановления исходных данных. Детектор можно выбрать независимо от этого этапа.
